# 안내 문구 작성 설계 — 여러 항목 + 강조 규칙

**작성일:** 2026-08-26
**상태:** 사용자 승인됨 (마커 규칙 2개, `label` 흡수하지 않음)

## 한 줄 요약

판매자가 안내 항목을 여러 개 만들 수 있게 하고, 설명 안에서 `<<제목>>` 과 `[[중요]]` 두 규칙으로 특정 문구를 강조할 수 있게 한다.

## 배경 — 지금 어긋나 있는 것

스토어프론트는 이미 안내를 **항목 배열**로 읽는다. `informationNavigationModel.js` 가 `안내` 탭 아래에 `사무소 안내` / `{분류} 안내` 자식 탭을 만들고, 각 패널이 `{ id, label, description }` 항목들을 그린다.

그런데 **빌더는 아직 문자열 하나만 쓴다.** `FieldSelectionDock` 이 `StorefrontTextFields` 로 `pageDescription` / `categoryDescription` 을 단일 값으로 받고, `useStorefrontBuilder` 의 `textDraft` 도 문자열 3개다. 저장하면 `normalizeInformationEntries` 의 레거시 폴백이 그것을 **항목 1개짜리 배열**로 바꾼다.

결과: 판매자는 스코프당 안내를 **1개밖에 못 만든다.** 읽는 쪽은 여러 개를 그릴 준비가 끝났는데 쓰는 쪽이 못 따라온 상태다.

강조 기능은 그 입력 행 안에 들어간다. 행이 없으면 붙일 자리가 없으므로 **항목 입력을 먼저 만들고 강조를 얹는다.**

## 결정

| # | 결정 | 근거 |
| --- | --- | --- |
| 1 | 빌더가 안내 항목 배열을 편집한다 (추가·삭제) | 읽는 쪽이 이미 배열이다 |
| 2 | 강조 규칙은 **2개뿐** — `<<제목>>`, `[[중요]]` | 사용자 결정 |
| 3 | 기호를 **두 번 겹친다** | `[비료]` `[신규]` 표기가 이 프로젝트 문구에 이미 있다 |
| 4 | `description` 에만 적용, `label` 은 마커를 해석하지 않는다 | `label` 은 이미 굵은 제목이다 |
| 5 | 파싱 결과는 조각 배열, 렌더는 `<strong>`/`<span>` | `innerHTML` 을 쓰지 않아 판매자 글이 태그로 해석될 여지가 없다 |
| 6 | 중요 색은 **고정 hex** | 브랜드 색을 따르면 초록 테마에서 "중요"가 초록이 되어 의미가 사라진다 |
| 7 | 입력창에 삽입 버튼과 **항상 보이는 설명 한 줄** | 판매자가 문법을 외우거나 툴팁을 hover 할 이유가 없어야 한다 |
| 8 | 재정렬 UI 없음, 항목 상한 10개 | YAGNI. 무제한이면 패널이 페이지가 된다 |

## 강조 규칙

```
<<봄철 밑거름>>              → 제목: 굵게 + 한 단계 크게
[[영세가격]]은 등록자 전용     → 중요: 굵은 빨강
[비료] 관련 안내입니다        → 평문 그대로
```

### 파서 계약

`parseInformationText(text) -> Array<{ text, style }>` — `style` 은 `'plain' | 'heading' | 'important'`.

동작 규칙:

- **안 닫히면 평문.** `[[영세가격` 은 여는 기호까지 포함해 그대로 보인다. 뒷글자를 삼키지 않는다.
- **중첩 없음.** `<<[[가격]]>>` 은 바깥만 제목으로 잡고 안쪽 `[[ ]]` 는 그 제목 안의 평문 글자다.
- **빈 마커는 평문.** `[[]]` 는 `[[]]` 그대로 보인다. 빈 `<strong>` 을 만들지 않는다.
- **개행 보존.** 조각 안의 `\n` 은 그대로 두고, 렌더는 지금처럼 `white-space: pre-line` 이 처리한다.
- **홑기호는 건드리지 않는다.** `[비료]`, `<20kg>` 모두 평문이다.

마커가 섞인 경우는 **가장 왼쪽에서 여는 쌍**을 잡는다. 닫히지 않는 여는 기호는 후보에서 빠지므로, `<<[[가격]]>>` 은 바깥 제목 하나로 잡히고 안쪽은 그 안의 평문이 된다.

### 스타일 값

| 역할 | 값 |
| --- | --- |
| 제목 | `font-weight: 700; font-size: 1.08em; color: #2f4a39` |
| 중요 | `font-weight: 700; color: #c62828` |

`#c62828` 은 패널 배경(거의 흰색) 위에서 대비 5.36:1 로 WCAG AA 를 통과한다. `em` 을 쓰는 이유는 설명 본문 크기가 바뀌어도 비율이 따라오게 하기 위해서다.

## 빌더 입력

```
사무소 안내
┌──────────────────────────────────────────────┐
│ 라벨   [ 영세가격 안내                    ]   │
│ 설명   [ <<봄철 밑거름>>                      │
│        [[영세가격]]은 등록자 전용입니다    ]  │
│        [ 제목 ] [ 중요 ]                      │  ← 삽입 버튼
│        << >> 제목 · [[ ]] 중요                │  ← 항상 보이는 설명
│                                    [ 삭제 ]   │
└──────────────────────────────────────────────┘
[ + 항목 추가 ]
```

- 공통 요소 탭 → 사무소 안내, 분류 탭 → 그 분류 안내
- 삽입 버튼: textarea 의 선택 영역을 감싼다. 선택이 없으면 커서 위치에 빈 쌍을 넣고 커서를 가운데로 옮긴다
- 설명 줄은 **툴팁이 아니라 상시 노출**한다. 판매자는 hover 하지 않는다
- 항목이 0개면 빈 행 하나를 자동으로 보여준다 — 추가 버튼만 있으면 무슨 화면인지 알기 어렵다
- 항목이 10개면 추가 버튼을 감춘다
- 미리보기는 타이핑하는 대로 갱신된다

## 테스트

- **파서** — 두 마커, 홑기호 무시, 안 닫힘, 중첩, 빈 마커, 개행, 세 기호 혼재.
- **렌더** — 제목/중요가 각각 별도 요소로 나오고 평문은 감싸지지 않는다. `innerHTML` 을 쓰지 않으므로 `<script>` 를 넣어도 글자로 보인다.
- **입력** — 추가·삭제가 배열을 바꾸고, 삭제해도 남은 행 값이 안 섞인다(= id key 가 실제로 필요함을 보이는 테스트). 삽입 버튼이 선택 영역을 감싼다.
- **브라우저** — 탭 전환, 강조가 실제로 보임, 줄바꿈 보존, 모바일 가로 스크롤 없음.

## 하지 않는 것

- 마커 중첩, 세 번째 마커
- 항목 드래그 재정렬
- 안내 문구의 AI 디자인 (앞선 결정대로 스코프 2개는 이미 제거됨)
- `label` 에서의 마커 해석
- 판매자가 임의 색을 고르는 것
