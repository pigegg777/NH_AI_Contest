# 엑셀 추출 검토 앱 스펙

## 목적

이 문서는 엑셀 추출 이후 사용자가 데이터를 검토하고 최종 선정하는 앱 흐름을 정의한다.

- 포함: 업로드 후 검토 흐름, `shadow` 작업 레이어, 유사상품 하이라이트, AI 질문, 최종 데이터 선정, Supabase 저장 전 사용자 판단
- 제외: 엑셀 헤더 탐지 규칙, 과세/영세 파싱 규칙, 유사도 계산 로직, 정규화 세부 기준. 이 내용은 추출 스킬 문서에서 다룬다.

## 핵심 원칙

1. 원본 데이터는 최대한 그대로 유지한다.
2. 사용자는 원본을 직접 덮어쓰기보다 `shadow` 작업 레이어를 통해 최종 선정한다.
3. AI는 추천과 질문만 수행하고 최종 확정은 사용자가 한다.
4. 분류값 `대분류/중분류/소분류/세분류`는 원본 그대로 사용한다.
5. `shadow` 데이터는 화면 세션 전용이며 영구 저장하지 않는다.

## 데이터 레이어

### 1. 원본 데이터

엑셀 또는 기존 저장 데이터에서 추출해야하는 기본 데이터다.
해당열을 제외한 열은 추출하지 않는다

- `product_code`
- `product_name`
- `tax_price`
- `zero_tax_price`
- `large_category`
- `medium_category`
- `small_category`
- `detail_category`
- `spec`
- `manufacturer`

원칙:

- 원본 데이터 자체를 수정하지 않는다

### 2. Shadow 데이터

검토와 최종 선정을 돕는 세션용 작업 데이터다.

용도:

- 유사도 높은 행 하이라이트
- AI 추천 1개 표시
- 충돌 비교 보조
- 사용자의 체크와 최종 선정 보조

원칙:

- shadow 체큰된 행은 shadow 행에 True 로 표시되어 저장됨
- shadow 열은 supabase에도 같이 저장됨

### 3. 최종 데이터

사용자가 최종 선정한 데이터다.

- Supabase로 저장하는 결과
- 이후 서비스 화면 렌더링에 사용하는 결과

## 업로드 흐름

1. 엑셀 업로드
2. 엑셀 읽기
3. 전체 상품 데이터 기반 작업 데이터 생성
4. AI 질문
5. `shadow` 체크
6. 최종 데이터 선정
7. Supabase 저장

### 보충 설명

- 유사도 높은 상품은 하이라이트로 표시한다.
- 사용자는 필요한 행만 체크해서 비교한다.
- 체크된 대상은 `shadow` 작업 레이어에서 검토한다.

## 수정 흐름

1. 기존 데이터 불러오기
2. 수정/추가 데이터 반영
3. `shadow`도 같이 갱신
4. 최종 데이터 선정
5. Supabase 저장

## 클라이언트와 서버 역할

### 클라이언트

- 업로드 직후 즉시 미리보기 생성
- 유사도 높은 행 하이라이트
- `shadow` 체크와 최종 선정 UI 제공
- AI 질문 결과와 추천 1개 표시

### 서버

- 원본 `xlsx` 재파싱
- 최종 저장 기준 역할 수행
- Supabase 저장 수행

## 유사상품 검토 UX

### 후보 기준

MVP 기준:

- 상품명 유사도
- 성분 정규화

제조업체는 유사상품 후보 판단 기준에서 제외한다.

### 화면 정책

- 유사도 높은 행은 색으로 하이라이트한다.
- 후보는 상위 3개까지 보여준다.
- AI는 추천 1개와 이유를 보여준다.
- 이유 예시:
  - 상품명 유사도 높음
  - 성분 유사도 높음

### 사용자 액션

- 같은 상품으로 본다
- 같은 상품 아님

원칙:

- 미해결 상태여도 `warn`으로 두고 진행 가능
- 자동 병합은 하지 않는다

## 가격 충돌 UX

다음 상황은 검토 대상으로 올린다.

- 같은 `product_code`
- 같은 세금 구분
- 가격이 2개 이상

이 경우:

- AI가 충돌 사실을 설명
- 사용자는 `행 통째로` 선택
- 선택된 행 값을 최종 반영

## 분류 정책

분류는 아래 원칙을 고정한다.

- `large_category`
- `medium_category`
- `small_category`
- `detail_category`

원칙:

- 원본 그대로 사용
- AI 추천 안 함
- 사용자 직접 수정 안 함

## 최종 선정 규칙

### 같은 상품으로 확정된 경우

- 사용자가 선택한 상품으로 화면에 렌더
- 사용자가 선택하지 않은 상품의 행은 shadow True 처리

### 같은 상품이 아닌 경우

- 병합하지 않음
- 각 상품을 그대로 유지

## 최종 저장 규칙

- 최종 저장은 서버가 다시 읽은 결과를 기준으로 한다.
- 저장 대상은 최종 선정된 데이터다.
- `shadow` 데이터도 저장

## 최종 저장 필드

서비스용 최종 데이터는 아래 필드 중심으로 유지한다.

```json
{
  "product_code": "2100031144112",
  "product_name": "엔케이플러스인(NK+인)",
  "tax_price": 14410,
  "zero_tax_price": 13100,
  "large_category": "비료",
  "medium_category": "무기질비료(원예용)",
  "small_category": "원예용비료",
  "detail_category": "원예용비료",
  "spec": "20kg",
  "manufacturer_display": "남해화학"
}
```

## 현재 범위에서 하지 않는 것

- 분류 자동 보정
- 분류 직접 수정
- override 재사용
- 성분표 기반 유사도 비교
- 제조업체 기반 유사도 점수 반영

## 추후 확장 후보

- 성분표 `concat` 후 성분 유사도 비교
- AI 비교 설명 고도화
